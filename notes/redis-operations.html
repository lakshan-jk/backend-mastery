🔴 Redis Operations Cheat Sheet

Redis is an in-memory key-value store. Every piece of data is stored under a key and retrieved by that key (O(1), instant). Below are the common operations, grouped by data type, with plain explanations.

💡 Node (ioredis) note: in code you call the lowercase method, e.g. await redis.set("k","v"), await redis.get("k"). The commands below are the raw Redis commands (same names).

1. Strings — basic key → value

CommandWhat it doesExample
SET key valueStore a value under a key (overwrites if exists)SET product:1 "Rug"
GET keyGet the value stored under a key (nil if missing)GET product:1
DEL keyDelete a key (used for cache invalidation)DEL product:1
EXISTS keyCheck if a key exists (1 = yes, 0 = no)EXISTS product:1
MSET / MGETSet/get multiple keys at onceMGET k1 k2 k3

2. Expiry / TTL — auto-delete after time

CommandWhat it doesExample
SET key val EX 30Set a key that auto-expires in 30 seconds cachingSET product:1 "Rug" EX 30
EXPIRE key 30Add a 30-second expiry to an existing keyEXPIRE product:1 30
TTL keyHow many seconds left before it expires (-1 = no expiry, -2 = gone)TTL product:1
PERSIST keyRemove the expiry (make it permanent)PERSIST product:1

3. Counters — atomic increment/decrement

Great for rate limiting, view counts, IDs. These are atomic (safe even with many clients at once).
CommandWhat it doesExample
INCR keyIncrease a number by 1INCR views:page1
DECR keyDecrease a number by 1DECR stock:1
INCRBY key 5Increase by a given amountINCRBY views:page1 5

4. Keys — finding keys

CommandWhat it doesExample
KEYS patternList all matching keys — ⚠️ blocks Redis, avoid in prod!KEYS product:*
SCAN cursorList keys in small batches — safe in prod (use instead of KEYS)SCAN 0 MATCH product:*
TYPE keyWhat data type is stored (string, hash, list...)TYPE product:1

5. Hashes — store an object (field → value)

Like a mini object/dictionary under one key. Good for storing a whole record (e.g. a user or product).
CommandWhat it doesExample
HSET key field valSet a field in the hashHSET user:5 name "Lakshan"
HGET key fieldGet one fieldHGET user:5 name
HGETALL keyGet all fields + valuesHGETALL user:5
HDEL key fieldDelete a fieldHDEL user:5 name

6. Lists — ordered sequence (queues)

Good for simple queues / recent-items. Push/pop from either end.
CommandWhat it doesExample
LPUSH / RPUSHAdd to the left / right endRPUSH tasks "job1"
LPOP / RPOPRemove + return from left / right endLPOP tasks
LRANGE key 0 -1Get a range (0 to -1 = all items)LRANGE tasks 0 -1
LLEN keyLength of the listLLEN tasks

7. Sets — unique unordered values

No duplicates. Good for "seen" checks, tags, unique visitors.
CommandWhat it doesExample
SADD key valAdd a value (ignores duplicates)SADD tags:1 "boho"
SMEMBERS keyGet all valuesSMEMBERS tags:1
SISMEMBER key valIs this value in the set? (1/0)SISMEMBER tags:1 "boho"
SREM key valRemove a valueSREM tags:1 "boho"

8. Sorted Sets — values ranked by a score

Each value has a score; auto-sorted. Great for leaderboards, priority queues, rankings.
CommandWhat it doesExample
ZADD key score valAdd a value with a scoreZADD leaderboard 100 "user5"
ZRANGE key 0 -1Get values sorted by score (low→high)ZRANGE leaderboard 0 -1
ZREVRANGE key 0 2Top N by score (high→low)ZREVRANGE leaderboard 0 2

9. Pub/Sub — messaging between servers

One publisher sends a message to a channel; all subscribers receive it. Fire-and-forget (not durable). Used as a WebSocket backplane.
CommandWhat it doesExample
PUBLISH channel msgSend a message to a channelPUBLISH chat:room1 "hi"
SUBSCRIBE channelListen to a channel for messagesSUBSCRIBE chat:room1

10. Server / utility

CommandWhat it does
FLUSHALLDelete ALL data (⚠️ careful!)
INFOServer stats (memory, clients, etc.)
DBSIZEHow many keys are stored
PINGHealth check → replies "PONG"
✅ The 6 you'll use 90% of the time: SET, GET, DEL, EXPIRE/SET ... EX, EXISTS, INCR. Everything else is situational.

Remember for interviews

  • Retrieve by KEY (not by value) — O(1) hash-table lookup → that's why it's fast.
  • TTL + DEL = caching (auto-expire + invalidate on update).
  • INCR = atomic → rate limiting / counters.
  • Avoid KEYS * (single-threaded, blocks) → use SCAN.
  • Pub/Sub = messaging backplane (fire-and-forget, not durable).
