LLD — Low-Level Design (inside the Orchestrator)

// one video request = a state machine
class VideoJob {
  id; userId; prompt;
  status: 'queued'|'scripting'|'rendering'|'stitching'|'done'|'failed';
  steps: Step[]; outputUrl?;
  advance()  // → next step
  retry() / markFailed(err)
}

// Strategy pattern — each step is swappable
interface Step { execute(job): Promise<Result> }
class ScriptStep  // LLM
class VoiceStep   // TTS
class VisualStep  // diffusion, GPU
class StitchStep  // FFmpeg

// runs steps in order, handles failure
class Orchestrator {
  async run(job) {
    for (step of job.steps) {
      r = await step.execute(job)
      if (!r.ok) return job.markFailed(r.error)
      job.advance()
    }
    job.status = 'done'
  }
}

// Adapter pattern — swap AI vendors freely
interface LLMProvider { generate(prompt) }
interface TTSProvider { synthesize(text) }
class OpenAIProvider / ElevenLabsTTS ...
Strategy — each Step swappable (script/voice/visual/stitch)
Adapter — Provider interfaces → swap OpenAI/Anthropic/ElevenLabs
State machine — VideoJob.status transitions
SOLID — one worker = one responsibility (SRP); providers open to extend (OCP)
🗣️ 60-sec pitch: "It's an agentic pipeline — the orchestrator plans script → voice → visuals → stitch, each an async worker off a queue since generation is slow and GPU-heavy. Steps use the Strategy pattern so they're swappable, and an Adapter layer swaps AI vendors without touching the pipeline. VideoJob is a state machine with idempotency so we never re-render the same job. Videos go to S3, served via CDN; GPU workers autoscale separately since they're the costly part; observability tracks render time and GPU cost."
